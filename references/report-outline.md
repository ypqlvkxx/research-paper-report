# 报告结构与篇幅

这是本用户的默认阅读报告模板。允许调整顺序、合并重复点或按论文类型改名，保持内容覆盖；不要求每点各占一节。默认中文、4-5 页 A4，正文约2500-3500个汉字，图表与出处保留可读字号。

## 内容顺序

**最前：论文身份与细粒度研究分类**

给出题名、作者、年份、会议 / 期刊及论文简称。用具体任务与对象分类，例如“建筑点云实例分割”“倾斜遥感单目建筑重建”“动态新视角合成 / 可变形3DGS”。不要将视觉骨干自动归为VLM，也不要混淆语义分割、实例分割与三维重建。

**0. 任务背景**

面向不了解此领域的读者，讲清任务用途、输入数据、必需先验和输出形式。涉及时间、视角、点云、传感器或外部地图时说明各自角色；区分训练监督与推理输入、逐场景优化与通用模型、粗体块与精细几何。

**1. 一句话总结**

一句话写出“用什么关键办法，解决什么问题”，避免只改写题名。

**2. 一段话总结＋问题出发点**

约100-180个汉字交代瓶颈、核心做法、最重要结果和结论边界。背景中已经解释过的内容不再展开。

**3. 前序方法时间线与不足**

精选3-5个阶段或关键工作，写清先前方法做法及作者指称的不足；紧接着简短评价这些不足是否成立、是否被夸大。作者陈述与自己的判断明确分开，不要求穷尽全领域。

**4. 直接工作基础**

列明本文建立在哪些论文、骨干、预训练模型、数据集或后处理上；标注直接实现基座、思想前序和比较对象。常用模块与既有技术不能重复算为本文发明。

**5. 核心创新与方法模块**

凝练为2-4个模块，解释每个模块解决哪个障碍以及如何连接。按需放一张原文方法图或1-2个关键公式；解释符号，不罗列全部网络层和损失。点明方法假设及其作用范围。

**6. 实验设置**

交代数据、地域 / 场景、输入分辨率、样本及划分、监督比例、基线；精选训练轮数 / 步数、优化器、学习率、骨干、硬件。报告可得的参数量、训练时长、显存 / 存储或FPS；未提供就标“未报告”，不能把模型文件大小直接换算成参数数目。代码补充的配置单独标明，不冒充论文设置。

**7. 主要结果：定量与定性配套**

用一个紧凑表或图集中给出代表性主结果和必要消融，包含关键强基线，保留指标单位及好坏方向。默认不要搬运所有表格。

若论文提供定性可视化，选1-2张最有解释力的原图，尽量保留GT / 相关基线 / 本文结果并排。说明具体改善和缺陷；代表性失败、负结果或补充材料中的反例不能因为影响故事而被忽略。没有可视化就说明缺失，不制造比较图。

**8. 证据是否支撑模块与普遍价值**

评估消融控制是否充分，数据、计算量和结构改进是否混杂；结果能否支持作者声称的泛化、效率、几何或时序性质。区分“未检验”“报告不清”与已观察到的失败。

**9. 质量与 simple but work 判断**

给出简短、平衡且有证据的评价。区分概念简单、实现简单、资源成本小这三件事；不以会议级别直接代替质量判断，不打虚构分数。

**10. 后续方向**

提出2-3条与已识别局限直接对应的方向，区分作者提出与自己的建议，优先说明值得验证的对照或改进。

**11. 意义与创新归属**

明确主要贡献偏方法、数据、训练机制、工程整合还是问题叙事。允许组合创新，但指出究竟改进了什么，避免泛泛“有重大意义”。

**末尾：来源与阅读范围**

列正文、补充材料及用到的项目 / 代码入口，保留稳定URL / DOI、版本、原图表编号和关键页码。缺少全文、附件、实现验证或复现的地方如实说明。若实际使用的其他技能要求注明工具来源，放在工具归属中，不当作本文实验依据。

## 建议分页

1. 研究分类、任务背景、两级总结、方法时间线与不足判断。
2. 直接基础、创新点、方法图与关键机制。
3. 实验设置、紧凑主结果和必要消融。
4. 1-2组主要定性比较与观察说明。
5. 证据边界、质量判断、未来方向、创新归属和出处。

这不是硬性分页。没有合适图片或论文较短时，可合并为4页；论文本身复杂或用户要求更多细节时再扩展。省字靠去重和筛选，不靠缩小字体或裁掉图例。
