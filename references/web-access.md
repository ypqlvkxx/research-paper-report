# 网页与 Zotero 链接的获取策略

仅在输入需要网络获取时阅读。目标是尽快得到足以精读的正文和图表，不把获取过程变成持续排障任务。

## 解析与选择

1. 从用户链接或 Zotero 引文识别题名、DOI 和入口 URL。Zotero 拖出的普通网址按论文网页处理，不需要连接或遍历整个 Zotero 文献库。
2. 读取入口，提取页面实际给出的 PDF、View PDF、补充材料或作者版本链接。优先正式版本；若使用预印本，标明版本，避免将不同版本的数值与图号混用。
3. 按完整性和速度选择 PDF 或 HTML 全文。确认下载内容确实是 PDF，并核对第一页题名 / 作者 / DOI，不能只看文件扩展名。若是 HTML，确认有完整的方法、实验和图表，而不是仅摘要。
4. 补充材料或官方代码只按分析需要获取。论文已完整时，缺少非关键附件不阻止报告；在阅读范围中说明。

## 明确停止，避免重复失败

- 首次正常访问后，若只是瞬时超时，可做一次短重试，或沿已知的直接开放获取链接尝试另一条路径。不要枚举猜测的 PDF URL、遍历镜像或不断换浏览器。
- 遇到 403、访问拒绝、登录、付费或人机验证，直接说明障碍。默认不尝试绕过、不反复点击验证、不要求用户接管浏览器；用户后续明确提出新尝试时再按新的指示处理。
- 无实质进展约 2 分钟就应结束获取；切换工具不重置等待预算。已正常下载且持续有进展可以合理等待，不需要为时间门槛中断成功传输。
- 大 PDF 下载慢且服务端支持字节范围时，可按需用少量并发范围请求；只有实际出现传输瓶颈才采用，不同时保留多个完整下载任务或无限重试。
- 新开的自动化浏览器通常不是用户原有浏览器会话。不要宣称沿用了其登录状态、验证结果或能控制其窗口，除非工具确实支持且已确认。

## 失败时的输出

用一小段说明：哪篇论文、尝试了什么入口、遇到什么实际错误、目前只拿到摘要 / 元数据还是没有内容，因此不能生成该篇全文精读报告。批量输入时继续处理其他条目，并在最终交付中保留失败项及原因。可以提示“提供本地 PDF 或可读的全文链接后即可继续”，不要求用户反复确认同一尝试，不生成貌似完整的空报告。

只拿到 Zotero 内部条目 ID / `zotero://` 链接而没有可用附件或外部 URL 时，说明无法从这个链接直接读取全文；不要将其解释为论文不存在。
